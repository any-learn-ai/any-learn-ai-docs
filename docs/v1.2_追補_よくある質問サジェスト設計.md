# AI個別指導システム 追補設計書
## よくある質問サジェスト機能 詳細設計

**追補バージョン:** 1.2.0  
**作成日:** 2026-07-26  
**対象:** 追補設計書 v1.1.0 への差分設計  
**変更箇所:** 質問受付フェーズ（OPEN_QA）全般  
**文字コード:** UTF-8 with BOM

---

## 概要

質問受付フェーズで「よくある質問」を3件サジェストし、タップ一つで質問できるようにする。  
疑問はあるが言葉にしにくいユーザーの「質問のハードルを下げる」ことが目的。

### 1.2 操作の流れ

```
【サジェスト質問をタップした場合】
  タップ → そのまま Q&A回答フェーズへ（入力欄のステップをスキップ）
  先生の回答が表示 → 「他に質問はありますか？」へ

    ※ タップした質問は「吹き出し（ユーザー側）」として
      チャット履歴に表示する（自分で入力したかのように見える）

【「他に質問を入力する」をタップした場合】
  → 従来どおり QA_INPUT 状態へ（テキスト/音声入力）

【「わかりました！」をタップした場合】
  → 確認問題フェーズへ（従来どおり）
```

### 1.3 フォローアップ時（QA_FOLLOWUP_PROMPT）の表示

Q&A回答後の「他に質問はありますか？」でも同様にサジェストを表示する。  
ただし **1回答えた質問は除外** し、残りのサジェストから表示する。

```
【QA_FOLLOWUP_PROMPT での表示（1問答えた後）】

  他に質問はありますか？

  ┌────────────────────────────────────────────────────────────┐
  │ ❓ なぜ分母が P(B) になるのですか？                       →│
  └────────────────────────────────────────────────────────────┘
  ┌────────────────────────────────────────────────────────────┐
  │ ❓ 別の例で説明してもらえますか？                         →│
  └────────────────────────────────────────────────────────────┘

  ┌──────────────────────────────┐  ┌──────────────────────────┐
  │  ✏️  他の質問を入力する     │  │  ✅  もう大丈夫！        │
  └──────────────────────────────┘  └──────────────────────────┘
```

### 1.4 再解説後の質問受付でのサジェスト

再解説後は元の3問ではなく、**つまずきポイントに特化した新しい3問**を生成して表示する。

```
【再解説後のサジェスト例（つまずき: 「条件事象の特定」の場合）】

  ┌────────────────────────────────────────────────────────────┐
  │ ❓ 「条件」と「求めたい事象」はどう区別するの？          →│
  └────────────────────────────────────────────────────────────┘

  │ ❓ もう一度最初の例で確認したい                           →│
```

## 2. サジェスト質問の生成設計

### 2.1 生成タイミング

**解説コンテンツ生成と同一 API 呼び出しで一括生成する。**  
別リクエストにすると「解説完了 → サジェスト待ち」という空白が生じるため、  
解説本文と同時に生成してフロントエンドにキャッシュしておく。

```
【生成タイミング図】

  セッション開始 or 次ステップ遷移
         ↓
  POST /micro-steps/{microStepId}/explanation
         ↓
  Claude Haiku 4.5 が1回のAPIコールで生成:
    ① 解説コンテンツ（contentItems）
    ② サジェスト質問3件（suggestedQuestions）   ← NEW
    ③ 再解説用サジェスト質問3件も事前生成しておく ← NEW
         ↓
  フロントエンドにキャッシュ
         ↓
  解説表示完了 → サジェストを即座に表示（待ち時間ゼロ）
```

### 2.2 サジェスト質問の設計原則

```
【良いサジェスト質問の条件】

  ✓ この概念を初めて聞いた人が本当に思うことを反映している
  ✓ 3問が互いに異なる「疑問の種類」をカバーする
  ✓ 短く自然な口語表現（「〜って何ですか？」「なぜ〜なの？」等）
  ✓ タップして回答が返ってきたとき、理解が深まる内容

【3問が担当する疑問カテゴリ】

  Q1: 用語・定義の確認
      例）「P(A∩B) って何ですか？」
          「○○という言葉の意味は？」

  Q2: 理由・仕組みの確認
      例）「なぜ分母が P(B) になるのですか？」
          「どうして○○になるの？」

  Q3: 例示・具体化の要求
      例）「別の例で説明してもらえますか？」
          「日常生活での例を教えて」

【禁止パターン】
  ✗ 「全部わかりません」のような広すぎる質問
  ✗ 確認問題で問われる内容そのまま（先に答えを教えてしまう）
  ✗ 次のマイクロステップの内容に踏み込む質問
  ✗ 3問が似たような質問の重複
```

### 2.3 カテゴリと質問テンプレート

Haikuがゼロから生成するが、内部的に以下の型を守って生成させる。

```typescript
type SuggestedQuestionCategory =
  | 'TERM_DEFINITION'       // 用語・定義の確認
  | 'REASON_MECHANISM'      // 理由・仕組みの確認
  | 'EXAMPLE_REQUEST'       // 例示・具体化の要求

interface SuggestedQuestion {
  category: SuggestedQuestionCategory
  text: string              // 実際に表示・送信される質問文（30文字以内）
  internalNote: string      // Haiku が回答を生成するときに使う補足（UI非表示）
}
```

## 3. 状態機械への変更（v1.1 差分）

### 3.1 状態変更なし

サジェスト質問は `EXPLANATION_COMPLETE` 状態で表示する。  
タップしたとき `QA_INPUT` を経由せず直接 `CHECKING_RELEVANCE` に遷移する。  
状態の追加は**不要**（遷移のトリガーを1種類追加するだけ）。

### 3.2 追加するアクション（MicroCycleAction に追加）

```typescript
// 追加するアクション（v1.1 の MicroCycleAction に追記）
type MicroCycleAction =
  | ... // 既存アクション
  | { type: 'SUGGESTED_QUESTION_TAPPED'; payload: SuggestedQuestion }
  //  ↑ これを追加。EXPLANATION_COMPLETE → CHECKING_RELEVANCE に遷移

// 追加する状態遷移テーブルの行
// | EXPLANATION_COMPLETE | サジェスト質問タップ | CHECKING_RELEVANCE | 質問テキストをQA_INPUT相当として処理 |
// | QA_FOLLOWUP_PROMPT   | サジェスト質問タップ | CHECKING_RELEVANCE | 同上 |
```

### 6.2 Q&A回答プロンプトへの変更（Claude Haiku 4.5）

サジェスト質問タップ時は `internalNote` を補足として渡し、回答の精度を高める。

```typescript
const QA_ANSWER_PROMPT = `
...（既存の指示）...

【質問の入力方法】: ${inputSource}   // "suggested" | "self_typed" | "voice"
${inputSource === 'suggested'
  ? `【回答補足メモ】: ${suggestedQuestion.internalNote}`
  : ''
}

// inputSource が "suggested" のとき internalNote を渡すことで、
// Haiku が「何を重点的に説明すべきか」を把握して回答できる
`
```

## 7. コンポーネント設計への変更（v1.1 差分）

### 7.1 QAChoicePanel コンポーネント（更新）

v1.1 の `QAChoicePanelProps` を拡張する。

```typescript
// v1.1 の Props を拡張
interface QAChoicePanelProps {
  mode: 'initial' | 'followup'
  onHasQuestion: () => void          // 既存（「他に質問を入力」ボタン用）
  onUnderstood: () => void           // 既存

  // ── NEW（v1.2 追加）──────────────────────────────────────────
  suggestedQuestions: SuggestedQuestion[]   // 表示するサジェスト（1〜3件）
  onSuggestedQuestionTap: (q: SuggestedQuestion) => void
  // ─────────────────────────────────────────────────────────────

  className?: string
}
```

**表示ロジック:**

```typescript
// QAChoicePanel 内部のレンダリングロジック
const QAChoicePanel = ({ mode, suggestedQuestions, onSuggestedQuestionTap, ... }) => {

  // すでにタップ済みのサジェストは除外して残りを表示
  const [usedCategories, setUsedCategories] = useState<Set<string>>(new Set())
  const visibleSuggestions = suggestedQuestions.filter(
    q => !usedCategories.has(q.category)
  )

  const handleSuggestedTap = (q: SuggestedQuestion) => {
    setUsedCategories(prev => new Set([...prev, q.category]))
    onSuggestedQuestionTap(q)
  }

  return (
    <div className="qa-choice-panel">
      <p className="qa-choice-panel__prompt">
        {mode === 'initial'
          ? 'よく聞かれる質問：'
          : '他に質問はありますか？'
        }
      </p>

      {/* サジェスト質問カード（残っているものだけ表示） */}
      <div className="qa-choice-panel__suggestions">
        {visibleSuggestions.map(q => (
          <button
            key={q.category}
            className="qa-suggestion-card"
            onClick={() => handleSuggestedTap(q)}
          >
            <span className="qa-suggestion-card__icon">❓</span>
            <span className="qa-suggestion-card__text">{q.text}</span>
            <span className="qa-suggestion-card__arrow">→</span>
          </button>
        ))}
      </div>

      {/* 自由入力 & わかった ボタン */}
      <div className="qa-choice-panel__actions">
        <button onClick={onHasQuestion}>
          ✏️ {mode === 'initial' ? '他に質問を入力する' : '他の質問を入力する'}
        </button>
        <button onClick={onUnderstood} className="primary">
          ✅ {mode === 'initial' ? 'わかりました！' : 'もう大丈夫！'}
        </button>
      </div>
    </div>
  )
}
```
