## 0. 作るもの（利用者の要求・原文）

> ・理解度診断の結果画面の、どのくらいのペースで学びますか？セクションの上に、
>   「AIが作成した学習プログラム」というセクションを追加し、
>   ここに作成した学習プログラムが表示される。
> ・この下に「学習プログラムをカスタマイズ」というテキストボックスが表示され、
>   フリーワードでカスタマイズできる。
> ・カスタマイズした結果、セクション数が変化したら、
>   どのくらいのペースで学びますか？に反映される
> ・この機能はStandard以上のみ使える

## 1. ⚠️ 最初に理解すべき「循環」

⚠️ **この機能は、既存の依存関係を逆向きにする。**ここを掴まないと、
実装の途中で必ず詰まる。

```
これまで:  ペースを選ぶ → セッション数が決まる → ★それを入力にプログラム生成
要求:      ★プログラムを見せる → カスタマイズ → セクション数 → ペースに反映
```

プログラム生成の入力は **2つ**ある（`core/src/domain/program-generation.ts:155-169`）。

| 入力 | もとの出どころ | ⚠️ 循環したか |
|---|---|---|
| `totalSessions` | 深さ（light/standard/deep） | ⚠️ **した** → 深さを廃止して解決 |
| `totalWeeks` | 学習期間（週） | ⚠️ **する** → **未解決。2.3 を読むこと** |

## 2. 決めたこと（⚠️ 蒸し返さないこと）

### 2.1 深さ（light / standard / deep）は廃止した ✅ 実装済み

⚠️ **深さは生成の入力なので、プログラムを先に見せるなら邪魔になる。**
見せたあとに変えられると、表示中のプログラムが無効になる。

学習量を調整したい人は、**プログラムを見てからカスタマイズする**
（Standard 以上）。⚠️ **利用者の方針: 「学習量を調整したかったら
Standard にしてね」。**

```
core/src/domain/study-schedule.ts
  DEPTH_FACTOR { light:0.5, standard:0.7, deep:1 }
    → STUDY_VOLUME_FACTOR = 1
```

⚠️ **1.0 を超える値を入れないこと。**AI が出すのは「しっかりやる場合の
一式」なので、増量は計画プロンプトの前提の外にある。番人が落ちる。

### 2.2 プログラムは確定より前に作る ✅ 中核は実装済み

⚠️ **確定時に作り直さないこと。**`plan-finalize.ts` に分岐を入れてある。

```ts
if (goal.programId) return;   // ⚠️ これを外すと3つ同時に起きる
```

  1. 原価が倍になる（コース生成 × 2）
  2. ⚠️ **カスタマイズした内容が消える**（`putProgram` が phases を丸ごと上書き）
  3. ⚠️ **前のプログラムが孤児になる**（新しい `programId` を採番）

⚠️ **3つめが最も悪い。**利用者は何も告げられず、調整した構成が
消えたことに気づけない。番人: `core/test/plan-finalize.test.ts`。

### 2.3 ⚠️ 週数（totalWeeks）の循環 — **未解決。ここが次の設計判断**

学習期間もペース欄にあり、プログラムより下に置く予定である。
⚠️ **だが `structureFor(totalSessions, totalWeeks)`
（`core/src/domain/program-quality.ts:57`）がフェーズ数の上限を週数から
決めている。**

**前セッションで提案した解決（未実装・未合意）:**

- 確定前の生成は、⚠️ **フォームの既定の週数を仮に使う**
- プレビューは ⚠️ **フェーズ名・ユニット名・セッション数だけを見せ、
  週数は出さない**（あとで変わるため）
- 下の期間・曜日は ⚠️ **「1日あたりの目安」だけに効く**

⚠️ **これでよいか、着手前に利用者へ確認すること。**
⚠️ **週数を出すと、あとで期間を変えたときに矛盾した数字が画面に残る。**

### 2.4 原価は「あとで」 ⚠️ 蒸し返さないこと

⚠️ **利用者から2度、明示的に指示があった。**

> 「原価計算はあとでやるとして、まず機能を作ってテストしたい」
> 「原価にこだわりすぎです。収支はあとで考えればいいのでまずは機能開発に集中して」

⚠️ **機能を作る手を止めて原価を議論しないこと。**
未処理の論点は**タスク #76 に隔離してある**（下の 5 章）。

## 4. 残っている作業

### C1 の残り: 確定前の生成を始める入口

いまは**確定するまで生成が始まらない。**プレビューを出すには、
確定前に `startProgramGeneration` を呼ぶ口が要る。

- 新しいエンドポイント（例: `POST /goals/{goalId}/program/preview`）
- ⚠️ **必要な入力**: `necessarySessions`（見積もり済み）+ 仮の `totalWeeks`（2.3）
- ⚠️ **二重に作らせない。**既に `programId` があれば 200 で返す
- ⚠️ 同時学習数の上限（`concurrentPrograms`）に当たるか要確認。
  **確定前のプレビューが枠を食う設計でよいのか、判断が要る**

### C2: 確定前カスタマイズ（タスク #74）

既存の `core/src/handlers/customize-program.ts` は
⚠️ **`isPlanConfirmed(goal)` を要求する**（:137）ので確定前は呼べない。

⚠️ **維持すべき制限（消さないこと）:**

| 制限 | 場所 |
|---|---|
| Standard 以上（`limits.programCustomization`） | :76-85 ⚠️ クレームが読めなければ**断る**（fail-close） |
| 学習開始後は不可 | :114-120 |
| 生成完了後のみ | :94-98 |
| ⚠️ **`quizPerStep` の持ち越し** | :151 ⚠️ **過去に黙って消した前科がある** |

### C3: 診断結果画面の再構成（タスク #75）

⚠️ **`report/page.tsx` は 1,300 行超。**セクションの並びは 406-463。

```
現在:  スコア → 分野別 → まとめ → PlanForm（期間・曜日 → 確定）
要求:  スコア → 分野別 → まとめ
       → ✦ AIが作成した学習プログラム
       → ✦ 学習プログラムをカスタマイズ（Standard 以上）
       → ✦ どのくらいのペースで学びますか？（確定）
```

⚠️ **カスタマイズでセッション数が変わったら、下の「1日あたりの目安」に
反映する。**`plannedSessions` ではなく**実プログラムのセッション数**を
使うことになる（`program.phases[].units[].estimatedSessions` の合計）。

## 6. ⚠️ このプロジェクトで守ること

### テスト

⚠️ **「緑になった」は結果ではない。**（2026-08-19 に、拒否テストが
全部空振りで緑になった実例がある。詳細は `認証設計の標準.md` 6章）

1. ⚠️ **モックに到達したことを数で確かめる**
2. ⚠️ **守りたい条件を1つずつ外して、落ちることを実測する**

### 実測

⚠️ **推測で断定しない。**2026-08-19 に Cognito の挙動で4回外した。
⚠️ **使い捨ての環境は数分で作れる。一般化する前に測る。**

### 死んだコード

⚠️ **働かなくなった判定・操作は消す。**「戻ったときに気づくため」と
書いて残しても、⚠️ **誰も読まない値は何にも気づかない。**
（`passwordless` で実害を出した）

### 運用

- ⚠️ **手元から `cdk deploy` しないこと。**必ず GitHub Actions 経由
- ⚠️ **状態を変える操作は、必ず先に確認を取ること**
- ⚠️ **API の形を変えるときは、消す側と読む側を同じ回で通すこと**
  （別リポジトリなので型検査は教えてくれない）
