## 1. システム概要

### 1.1 プロジェクト目的

本システムは、AIを活用した完全個別対応の学習支援プラットフォームである。ユーザーが自由に学習テーマを指定するだけで、AIが現在の理解度を診断し、最適な学習プログラムを自動生成する。先生アバターによるインタラクティブな指導を通じ、「本物の個別指導教室」に近い学習体験を提供することを目的とする。

### 1.2 主要ユーザーシナリオ

```
【ユーザー操作フロー全体像】

① 学習テーマ指定（フリーテキスト or 音声）
   例：「中学受験難関校レベルの確率をマスターしたい」
   例：「自動車免許の筆記試験対策をしたい」
         ↓
② 目標設定チャット（AI）
   ・到達レベルの確認
   ・学習期間の確認
   ・週当たり学習時間の確認
   ・目標内容の合意
         ↓
③ アセスメント実施（約20問）
   ・AI生成の診断問題
   ・タイピング or 音声で回答
   ・先生アバターが進行
         ↓
④ 診断レポート表示
   ・強化すべき点の可視化
   ・できている点の可視化
   ・分野別スコアチャート
         ↓
⑤ 学習プログラム生成・確認
   ・フェーズ・ユニット・セッション構成
   ・推定完了期間の表示
         ↓
⑥ 学習実施（繰り返し）
   ・先生アバター + 音声 + 吹き出しで指導
   ・テキスト・画像・アニメーションで解説
   ・いつでも自由質問可能
   ・進捗はいつでも確認可能
```

### 1.3 主要機能一覧

| 機能ID | 機能名 | 概要 |
|--------|--------|------|
| F-001 | 学習テーマ入力 | フリーテキスト・音声によるテーマ指定 |
| F-002 | 目標設定チャット | AIとの対話による学習目標の設定・合意 |
| F-003 | アセスメント | 約20問のAI生成問題による理解度診断 |
| F-004 | 診断レポート | 強み・弱みの可視化レポート生成 |
| F-005 | 学習プログラム生成 | AIによる個別最適化学習計画の自動作成 |
| F-006 | 学習セッション | アバター先生によるインタラクティブ指導 |
| F-007 | 自由質問 | セッション中のいつでも質問機能（脱線防止機構付き） |
| F-008 | 進捗管理 | 学習進捗のリアルタイム追跡・可視化 |
| F-009 | 音声入出力 | Amazon Polly（読み上げ）・Transcribe（認識） |
| F-010 | アバター表示 | 先生キャラクターの状態連動アニメーション |

### 2.3 AIモデル利用戦略

Anthropic Claude APIを直接利用（AWS Bedrockは使用しない）。

#### モデル選定基準

```
【Claude Opus 4.8 を使用する処理】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  用途: 高品質な推論・生成が必要なタスク
  特徴: 最高品質だが応答にやや時間がかかる
  ユーザー影響: バックグラウンドで実行（待ち時間許容）

  ① アセスメント問題生成（20問一括）
     - 学習テーマの本質を理解した良問生成
     - 難易度バランスの制御
     - ひっかけ問題の作成

  ② 診断レポート生成
     - 20問の回答パターンから複合的分析
     - 強み・弱みの言語化
     - 個別化されたコメント生成

  ③ 学習プログラム生成
     - 長期学習計画の立案
     - フェーズ・ユニット・セッションの階層設計
     - ユーザー特性を反映したカスタマイズ

【Claude Haiku 4.5 を使用する処理】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  用途: 低レイテンシ・高頻度な対話タスク
  特徴: 高速・低コスト、品質も十分
  ユーザー影響: リアルタイム応答（2秒以内）

  ① 学習セッション中の会話・フィードバック
     - 回答の正誤評価とコメント
     - ヒント提供
     - 次ステップへの誘導

  ② 自由質問への回答
     - 学習範囲内の質問への即時応答

  ③ 脱線検知（分類タスク）
     - 質問が学習テーマと関連するか判定

  ④ 目標設定チャット

  ⑤ アセスメント中の個別回答評価
```

#### コスト最適化施策

| 施策 | 内容 | 効果 |
|------|------|------|
| Prompt Caching | システムプロンプトに`cache_control`設定 | Opus使用コスト最大90%削減 |
| モデル使い分け | Opus/Haikuの適切な切り替え | 平均コストをOpus単独比で約70%削減見込み |
| TTS音声キャッシュ | S3へPolly出力をキャッシュ・再利用 | Pollyコスト削減、応答速度向上 |
| Batch API活用 | アセスメント問題生成に非同期Batch API検討 | Opus利用コスト最大50%削減 |
| 会話履歴の圧縮 | 長期セッション時に古い履歴を要約して圧縮 | 入力トークン数の抑制 |

### 2.4 音声処理設計

#### テキスト→音声（TTS）：Amazon Polly

```
【TTSフロー】

フロントエンド
    │ テキスト送信（POST /tts）
    ▼
Lambda (ttsHandler)
    │
    ├─ S3キャッシュ確認（テキストのSHA256ハッシュをキー）
    │       ヒット ─────────────────────────┐
    │       ミス                            │
    ▼                                      │
Amazon Polly (Neural TTS)                  │
    │ MP3音声生成                           │
    ▼                                      │
S3 (tts-cache バケット)に保存              │
    │                                      │
    ▼                                      │
Presigned URL生成 ←─────────────────────────┘
    │
    ▼
フロントエンド（Audio要素で再生）

【設定】
・エンジン: neural（高品質）
・音声ID: Kazuya（男性・標準）/ Tomoko（女性）※ユーザー選択可
・形式: MP3、サンプルレート: 22050Hz
・キャッシュTTL: 30日（頻出フレーズを長期キャッシュ）
```

#### 音声→テキスト（STT）：Amazon Transcribe

```
【STTフロー】

ユーザーがマイクボタン押下
    │
    ▼
MediaRecorder API（ブラウザ標準）
    │ 音声データ収集（WebM/Opus形式）
    ▼
Lambda (sttHandler) ※Presigned URL経由でS3アップロード
    │
    ▼
Amazon Transcribe StartTranscriptionJob
    │ 非同期処理（数秒〜十数秒）
    ▼
転写結果をWebSocket or ポーリングで取得
    │
    ▼
フロントエンド（テキスト入力欄に表示・確認）
    │ ユーザーが内容確認後に送信
    ▼
通常のテキスト入力と同様に処理

【設定】
・言語: ja-JP（日本語）
・メディア形式: webm
・最大発話時間: 60秒
・自動句読点: 有効
```

### 2.5 セキュリティ設計

#### 認証・認可フロー

```
1. ユーザーがメール/パスワードでCognito認証
2. CognitoがJWT（ID Token + Access Token）を発行
3. フロントエンドがTokenをSecure httpOnly Cookie or Memory Storeに保管
4. API呼び出し時にAuthorizationヘッダにBearer Tokenを付与
5. API GatewayのLambda AuthorizerがJWTを検証
6. 検証成功後、Lambda関数にuserIdを渡す
7. Lambda内でDynamoDBアクセス時にuserIdの所有権を確認
```

#### APIキー管理

- Claude API KeyはAWS Secrets Managerに保管
- Lambda実行ロールにSecretsManagerReadWrite権限を付与
- Lambda起動時にSecrets Managerから動的取得（キャッシュ有り）
- 定期的なローテーション設定（90日）

#### データ保護

| データ種別 | 保護方法 |
|-----------|----------|
| DynamoDBデータ | AWS管理キーによる保存時暗号化 |
| S3データ | SSE-S3による保存時暗号化 |
| 通信経路 | TLS 1.3 (HTTPS全通信) |
| ユーザー音声データ | 処理後S3から自動削除（7日） |
| Claude APIへの送信 | 最小限の個人情報（userId以外は匿名） |

### 2.6 データフロー設計

#### 学習セッション中のデータフロー（ストリーミング）

```
【セッション中のリアルタイム応答フロー】

フロントエンド
  ① POST /sessions/{id}/messages
     Body: { userMessage: "...", stepId: "..." }
         │
         ▼
  Lambda (sessionResponder)
  ② DynamoDBから会話履歴取得
  ③ システムプロンプト + 履歴 + ユーザーメッセージを構築
  ④ Claude Haiku 4.5 API呼び出し（ストリーミング）
  ⑤ Lambda Response Streamingでフロントへ転送
         │ SSEチャンク（テキストデルタ）
         ▼
  フロントエンド
  ⑥ SpeechBubbleコンポーネントがテキストをリアルタイム表示
  ⑦ 文章区切り（。！？）を検出したら並行でTTSリクエスト
  ⑧ TTS音声の準備ができたら再生
  ⑨ ストリーミング完了後、DynamoDBに履歴を保存
  ⑩ アバター状態を「話し中」→「待機中」に遷移
```

## 3. 機能要件定義

### 3.1 学習テーマ入力（F-001）

#### 機能概要

ユーザーが最初に学習したい内容をフリーテキストまたは音声で指定する。

#### 入力仕様

| 入力方法 | 詳細 |
|----------|------|
| テキスト入力 | 最小10文字〜最大500文字。Placeholderで入力例を提示 |
| 音声入力 | マイクボタン押下で録音開始、最大60秒。Transcribeで文字変換後、確認欄に表示してから送信 |

#### 入力例（プレースホルダー表示用）

- 「中学受験難関校レベルの確率・統計をマスターしたい」
- 「自動車免許（普通車AT）の筆記試験に1ヶ月で合格したい」
- 「TOEIC 800点を目指したい（現在600点レベル）」
- 「Pythonで機械学習の基礎を学びたい」

#### 送信後のAI処理

Claudeが以下を解析してJSON形式で返却：

```json
{
  "subject": "確率・統計",
  "context": "中学受験",
  "targetLevel": "難関校合格レベル",
  "estimatedDurationWeeks": 12,
  "weeklyStudyHours": 5,
  "prerequisites": ["四則演算", "分数の概念"],
  "clarificationNeeded": ["現在の学年", "週当たり学習可能時間"]
}
```

### 3.2 目標設定チャット（F-002）

#### チャットフロー状態機械

```
状態: INITIAL
  → AIが入力内容を解析したサマリーを提示
  → 確認が必要な項目をリストアップ

状態: CONFIRMING_LEVEL
  → 到達目標レベルの詳細確認
  → 例：「難関校とは具体的にどの学校を想定していますか？」

状態: CONFIRMING_DURATION
  → 学習期間の確認・提案
  → 例：「現状から判断すると3ヶ月が適切ですが、いかがですか？」

状態: CONFIRMING_SCHEDULE
  → 週当たり学習時間の確認
  → 例：「週に何時間くらい学習できそうですか？」

状態: GOAL_SUMMARY
  → 合意した目標のサマリーを表示
  → 「この内容で進める」または「変更する」を選択

状態: AGREED
  → アセスメントフェーズへ遷移
```

#### 脱線防止機構（目標設定フェーズ）

Claude Haiku 4.5のシステムプロンプトに以下を設定：

```
あなたは優しい個別指導の先生です。
現在のタスクは「学習目標の設定」のみです。
ユーザーが学習と無関係な話題を持ち出した場合、
「それについては学習が始まってから話しましょう！
まずは目標を決めましょう」と優しく誘導してください。
```

### 3.3 アセスメント機能（F-003）

#### 問題生成仕様（Claude Opus 4.8）

| 項目 | 仕様 |
|------|------|
| 問題数 | 20問（固定） |
| 難易度分布 | 易（30%）: 6問 / 中（50%）: 10問 / 難（20%）: 4問 |
| 問題タイプ | 選択式（4択）: 15問 / 記述式: 4問 / 音声回答対応: 1問 |
| 生成タイミング | 目標設定合意直後に一括生成（Opus API呼び出し1回） |
| 生成所要時間 | 最大30秒（ローディング画面でカバー） |
| 問題形式 | テキスト主体。画像が有効な場合はS3上のプリセット問題画像を参照 |

#### 回答評価仕様（Claude Haiku 4.5）

- 選択式：正解/不正解の即時判定（DB照合）
- 記述式：Claude Haiku 4.5が模範解答と比較し部分点を算出
- 各問にかかる評価時間：1秒以内（Haiku使用）
- アセスメント中はユーザーに正誤をフィードバックしない（結果への偏りを防ぐ）

#### 回答データ構造

```json
{
  "assessmentId": "asmnt_xxx",
  "userId": "usr_xxx",
  "questions": [
    {
      "questionId": "q001",
      "type": "multipleChoice",
      "difficulty": "easy",
      "topic": "確率の基礎",
      "question": "コインを2回投げたとき、2回とも表が出る確率は？",
      "choices": ["1/2", "1/4", "1/3", "2/3"],
      "correctAnswer": "1/4",
      "userAnswer": "1/4",
      "isCorrect": true,
      "score": 1.0,
      "responseTimeSeconds": 12
    }
  ],
  "totalScore": 72,
  "completedAt": "2026-07-26T10:30:00Z"
}
```

### 3.4 診断レポート（F-004）

#### 分析項目

Claude Opus 4.8が20問の回答パターンから以下を分析：

| 分析項目 | 内容 |
|----------|------|
| 総合スコア | 0〜100点のスコア |
| 分野別スコア | 学習テーマをサブトピックに分解し各スコア算出 |
| 強化すべき点 | 誤答・不正確な回答が多い領域のTop3〜5 |
| できている点 | 正答率の高い領域のTop3〜5 |
| 学習スタイル推定 | 回答パターンから「計算は得意だが概念理解が弱い」等を推定 |
| 推奨学習アプローチ | 個人特性に合わせた学習方法の提案 |

### 3.5 学習プログラム生成（F-005）

#### プログラム構造（階層）

```
LearningProgram（学習プログラム全体）
  └─ Phase（フェーズ：大きな学習段階）
       ├─ Phase 1: 基礎固め（2週間）
       ├─ Phase 2: 応用力強化（3週間）
       └─ Phase 3: 実践・演習（2週間）
            └─ Unit（ユニット：テーマ単位の学習）
                 ├─ Unit 1-1: 確率の基礎概念（3セッション）
                 └─ Unit 1-2: 場合の数（4セッション）
                      └─ Session（セッション：1回の学習単位、20〜30分）
                           ├─ Step 1: 概念説明
                           ├─ Step 2: 例題解説
                           ├─ Step 3: 練習問題 × 3
                           └─ Step 4: まとめ・次回予告
```

#### 生成プロンプト設計方針

Claude Opus 4.8への入力：
- ユーザーの学習目標（合意済み）
- 診断レポート全文（強み・弱みの詳細）
- 利用可能な期間・週当たり学習時間
- 出力フォーマット（JSON Schema）

生成物：全フェーズ・ユニット・セッション構成のJSON（約5,000〜10,000トークン規模）

### 3.6 自由質問機能（F-007）

#### 脱線検知フロー

```
ユーザーが質問ボタンを押して質問を入力
    │
    ▼
Claude Haiku 4.5 による関連度チェック
（学習テーマとの関連度を0〜1で評価）
    │
    ├─ 関連度 >= 0.7 → 「学習に関連する質問」として回答
    │   Claude Haiku 4.5 が回答 → 吹き出し表示 + Polly読み上げ
    │   「よい質問ですね！」とアバターがリアクション
    │
    └─ 関連度 < 0.7 → 「脱線質問」として誘導
        アバターが「今は〇〇の学習中だよ！
        その質問は学習が終わってからにしよう！
        メモしておいてあげるね」と応答
        → 質問内容をユーザーの「あとで聞く」リストに保存
```

```typescript
// TeacherAvatar.tsx（実装概要）
const TeacherAvatar: React.FC<TeacherAvatarProps> = ({
  state, size = 'md', onAnimationComplete
}) => {
  const lottieRef = useRef(null)
  const [currentAnimation, setCurrentAnimation] = useState(state)

  useEffect(() => {
    const config = ANIMATION_CONFIG[state]
    // 現在のアニメーションを停止し、新しいアニメーションに切り替え
    lottieRef.current?.stop()
    setCurrentAnimation(state)
    lottieRef.current?.play()

    if (!config.loop) {
      // 1回再生後にonAnimationCompleteを呼び出し
      const timeout = setTimeout(onAnimationComplete, config.durationMs)
      return () => clearTimeout(timeout)
    }
  }, [state])

  return (
    <div className={cn(SIZE_CLASSES[size], 'relative')}>
      <Lottie
        ref={lottieRef}
        animationData={LOTTIE_FILES[currentAnimation]}
        loop={ANIMATION_CONFIG[currentAnimation].loop}
      />
    </div>
  )
}
```

### 5.3 SpeechBubble コンポーネント

#### 概要

AIが生成したメッセージをタイピングアニメーションで表示し、Claude APIのServer-Sent Eventsストリーミングに対応する。

#### Props定義

```typescript
interface SpeechBubbleProps {
  /** ストリーミングモード: trueの場合content追記でアニメーション */
  isStreaming: boolean
  /** 表示するテキスト（ストリーミング時は逐次追記） */
  content: string
  /** タイピング速度 (ms/文字) - ストリーミング非使用時 */
  typingSpeed?: number
  /** 表示位置（アバターの右or左） */
  position?: 'left' | 'right'
  /** Polly読み上げ完了後に呼び出すコールバック */
  onReadingComplete?: () => void
  className?: string
}
```

#### ストリーミング対応実装概要

```typescript
const SpeechBubble: React.FC<SpeechBubbleProps> = ({
  isStreaming, content, typingSpeed = 30, position = 'right', onReadingComplete
}) => {
  const [displayedText, setDisplayedText] = useState('')
  const [pendingTTS, setPendingTTS] = useState('')
  const prevContentRef = useRef('')

  useEffect(() => {
    if (isStreaming) {
      // ストリーミング: contentの差分を即時表示
      setDisplayedText(content)

      // 文末文字（。！？）を検出したらPendingTTSに追加
      const newPart = content.slice(prevContentRef.current.length)
      prevContentRef.current = content
      const sentences = newPart.match(/[^。！？]*[。！？]/g) || []
      if (sentences.length > 0) {
        setPendingTTS(prev => prev + sentences.join(''))
      }
    } else {
      // 非ストリーミング: タイピングアニメーション
      let i = 0
      const timer = setInterval(() => {
        setDisplayedText(content.slice(0, i + 1))
        i++
        if (i >= content.length) clearInterval(timer)
      }, typingSpeed)
      return () => clearInterval(timer)
    }
  }, [content, isStreaming])

  return (
    <div className={cn('speech-bubble', `speech-bubble--${position}`)}>
      <div className="speech-bubble__text">
        {displayedText}
        {isStreaming && <span className="speech-bubble__cursor">▌</span>}
      </div>
    </div>
  )
}
```

| `error` | ⚠️ | エラー（詳細） | 赤 |

#### Amazon Transcribeとの連携フロー

```
1. ユーザーが録音ボタンを押す
2. navigator.mediaDevices.getUserMedia() でマイク権限取得
3. MediaRecorder APIで録音開始（MIME: audio/webm;codecs=opus）
4. 録音停止時にBlobデータを取得
5. Presigned URL取得API（GET /uploads/presigned-url）を呼び出し
6. S3にBlob直接アップロード（PUT）
7. Transcribe開始API（POST /transcribe）を呼び出し
8. ポーリングまたはWebSocketでジョブ完了を確認
9. 文字起こし結果をonTranscriptコールバックで返却
10. S3上の音声ファイルを削除（POST /uploads/cleanup）
```


### 8.4 ストリーミング実装（Lambda Response Streaming）

```typescript
// Lambda設定（CDKコード例）
const sessionResponderFn = new lambda.Function(this, 'SessionResponder', {
  runtime: lambda.Runtime.NODEJS_22_X,
  handler: 'index.handler',
  memorySize: 512,
  timeout: cdk.Duration.seconds(60),
})

// ストリーミング有効化
const fnUrl = sessionResponderFn.addFunctionUrl({
  authType: lambda.FunctionUrlAuthType.AWS_IAM,
  invokeMode: lambda.InvokeMode.RESPONSE_STREAM,  // ← ストリーミング有効化
  cors: { allowedOrigins: ['https://app.domain.com'] }
})
```

```typescript
// sessionResponder Lambda実装概要
import { streamifyResponse, ResponseStream } from 'lambda-stream'
import Anthropic from '@anthropic-ai/sdk'

export const handler = streamifyResponse(async (event, responseStream) => {
  const client = new Anthropic({ apiKey: await getApiKey() })

  // HTTPメタデータを先に送信
  const metadata = { statusCode: 200, headers: { 'Content-Type': 'text/event-stream' } }
  responseStream.setContentType('application/vnd.awslambda.http-integration-response')
  responseStream.write(JSON.stringify(metadata))

  // Claude APIストリーミング呼び出し
  const stream = await client.messages.stream({
    model: 'claude-haiku-4-5',
    max_tokens: 1024,
    system: buildSystemPrompt(sessionContext),
    messages: buildMessages(conversationHistory, userMessage)
  })

  // チャンクをSSE形式でフロントへ転送
  for await (const chunk of stream) {
    if (chunk.type === 'content_block_delta') {
      const sseData = `data: ${JSON.stringify({
        type: 'text_delta',
        delta: chunk.delta.text
      })}\n\n`
      responseStream.write(sseData)
    }
  }

  // 完了シグナル
  responseStream.write(`data: ${JSON.stringify({ type: 'message_stop' })}\n\n`)
  responseStream.end()

  // 非同期でDynamoDBに会話履歴を保存（レスポンス後）
  await saveConversationHistory(sessionId, messages)
})
```
