## 1. 設計方針

### 1.1 基本コンセプト

実際の優秀な家庭教師が行う指導スタイルを忠実に再現する。

```
【良い個別指導の特徴】
  ✓ 一度に大量の情報を与えない
  ✓ 小さな単位で区切り、都度理解を確認する
  ✓ 疑問はその場で即座に解消する
  ✓ 理解の確認は「質問するだけ」でなく「問いを解かせる」
  ✓ 間違えたら責めず、別のアプローチで再挑戦させる
  ✓ 正解したら具体的に何が良かったかを伝える
```

### 1.2 マイクロサイクルの定義

**1マイクロサイクル = 1概念の解説 → 質問受付 → 確認問題**

このサイクルを最小単位として繰り返し積み上げることで学習を進める。

| 概念の例（確率の場合） | 1マイクロサイクルの対象 |
|---------------------|----------------------|
| 「確率の定義」を理解する | ✅ 1サイクル |
| 「余事象の公式」を理解する | ✅ 1サイクル |
| 「加法定理」を理解する | ✅ 1サイクル |
| 「確率の全単元」を理解する | ❌ 大きすぎる（複数サイクルに分割必須） |

### 1.3 設計上の重要原則

| 原則 | 詳細 |
|------|------|
| **解説の原子性** | 1マイクロサイクルで扱う概念は必ず1つ。複数概念の混在禁止 |
| **質問ファースト** | 確認問題の前に必ず質問受付フェーズを挟む |
| **強制前進禁止** | ユーザーが「分かった」と言うまで次に進まない |
| **失敗の安全性** | 確認問題の不正解は責めず、必ず別アプローチで再解説 |
| **コンテキスト保持** | 同一サイクル内の会話は全て記憶し、再解説に活かす |
| **脱線の適切な管理** | Q&Aフェーズ中の脱線質問は「あとで聞くリスト」へ |

### 2.2 具体的な会話例

```
【「条件付き確率の定義」マイクロサイクルの会話例】

━━ ① 解説フェーズ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
先生: 「今日は「条件付き確率」を学びましょう！

      まず、条件付き確率とは何かを説明しますね。

      「条件付き確率 P(A|B)」とは、
      『Bという出来事が起きたとわかっているとき、
       さらにAも起きる確率はどれくらいか？』
      ということです。

      例えば、こんな状況を想像してみてください。

      ─────────────────────────────────────
      🌧️ 例：天気の問題
       「明日雨が降る確率は30%」← これが普通の確率
       「今、空が曇っているとわかった上で、
        明日雨が降る確率は？」← これが条件付き確率！
      ─────────────────────────────────────

      曇り空という「条件」がつくことで、確率が変わるのがポイントです。
      式で書くと：P(A|B) = P(A∩B) / P(B)
      と表せます。」

━━ ② 質問受付フェーズ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
先生: 「ここまでどうですか？
       疑問に思ったことや、もう少し詳しく聞きたいことはありますか？」

      [❓ 質問があります]  [✅ 分かりました！]

─── ユーザーが「質問があります」を選択した場合 ───────────────────
ユーザー: 「P(A∩B)って何ですか？」

先生: 「良い質問です！
       A∩B（AとBの積事象）は、
       『AとBが両方同時に起きる』という出来事のことです。

       天気の例で言うと、
       ・A = 明日雨が降る
       ・B = 今日が曇りである
       ・A∩B = 今日が曇りで、かつ明日も雨が降る

       [ベン図アニメーション：AとBの重なり部分を強調表示]

       この重なった部分がA∩Bです。わかりましたか？」

先生: 「他に質問はありますか？」

ユーザー: 「大丈夫です！」
      → 確認問題フェーズへ進む

━━ ③ 確認問題フェーズ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
先生: 「では、理解できているか確認しましょう！

       ─────────────────────────────────────
       ❓ 確認問題
       
       袋の中に赤玉3個・白玉2個・青玉1個が入っています。
       「1個取り出したら白玉だった」とわかっています。
       
       このとき、「取り出した玉が白玉である確率」を
       P(A|B)の形で表すとき、P(B)は何の確率ですか？
       ─────────────────────────────────────」

ユーザー: 「白玉を取り出す確率です」

━━ ④ 評価フェーズ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
━━ ⑤ 正解フィードバック ━━━━━━━━━━━━━━━━━━━━━━━━━━━━
先生（🎉アニメーション）:
      「正解！完璧です！
       P(B)は「条件となる出来事の確率」、
       つまり今回は「白玉を取り出す確率（2/6）」です。
       
       条件付き確率の分母が何を表すか、
       しっかり理解できていますね！」
```

## 3. 状態機械設計

### 3.1 マイクロサイクル状態定義

```typescript
type MicroCycleState =
  // ── 解説フェーズ ─────────────────────────────────
  | 'GENERATING_EXPLANATION'   // AIが解説コンテンツを生成中
  | 'DISPLAYING_EXPLANATION'   // 解説を表示・読み上げ中
  | 'EXPLANATION_COMPLETE'     // 解説完了・ユーザー選択待ち

  // ── 質問受付フェーズ ──────────────────────────────
  | 'OPEN_QA_PROMPT'           // 「質問はありますか？」を表示中
  | 'WAITING_FOR_QA_CHOICE'    // ユーザーの選択待ち（質問する/わかった）
  | 'QA_INPUT'                 // 質問テキスト/音声入力中
  | 'CHECKING_RELEVANCE'       // 脱線チェック中（Claude Haiku）
  | 'GENERATING_QA_ANSWER'     // 質問への回答生成中（ストリーミング）
  | 'DISPLAYING_QA_ANSWER'     // 回答表示・読み上げ中
  | 'QA_FOLLOWUP_PROMPT'       // 「他に質問はありますか？」を表示中
  | 'QUESTION_DEFERRED'        // 脱線質問→メモして学習継続

  // ── 確認問題フェーズ ──────────────────────────────
  | 'GENERATING_QUIZ'          // 確認問題を生成中（Claude Haiku）
  | 'DISPLAYING_QUIZ'          // 確認問題を表示・読み上げ中
  | 'WAITING_FOR_ANSWER'       // ユーザー回答入力待ち
  | 'ANSWER_RECORDING'         // 音声回答録音中
  | 'SUBMITTING_ANSWER'        // 回答送信・採点中

  // ── フィードバックフェーズ ────────────────────────
  | 'DISPLAYING_CORRECT'       // 正解フィードバック表示
  | 'DISPLAYING_PARTIAL'       // 部分正解フィードバック表示
  | 'DISPLAYING_INCORRECT'     // 不正解フィードバック表示

  // ── 再解説フェーズ ────────────────────────────────
  | 'GENERATING_RE_EXPLANATION' // 再解説コンテンツ生成中
  | 'DISPLAYING_RE_EXPLANATION' // 再解説表示中

  // ── 完了 ──────────────────────────────────────────
  | 'MICRO_STEP_COMPLETE'      // このマイクロステップ完了
  | 'SESSION_COMPLETE'         // セッション内全ステップ完了
  | 'ERROR'                    // エラー
```

| `DISPLAYING_QUIZ` | 読み上げ完了 | `WAITING_FOR_ANSWER` | 回答入力欄活性化 |

| `DISPLAYING_CORRECT` | フィードバック完了 | `MICRO_STEP_COMPLETE` | 習熟度更新・次ステップ |
| `DISPLAYING_PARTIAL` | フィードバック完了 | `MICRO_STEP_COMPLETE` | 低スコアで習熟度更新 |
| `DISPLAYING_INCORRECT` | フィードバック完了 | `GENERATING_RE_EXPLANATION` | 再解説生成 |
| `GENERATING_RE_EXPLANATION` | 生成完了 | `DISPLAYING_RE_EXPLANATION` | 再解説表示 |
| `DISPLAYING_RE_EXPLANATION` | 表示完了 | `EXPLANATION_COMPLETE` | 再度質問受付へ |

### 3.3 不正解回数による分岐

```
確認問題 不正解回数ごとの処理:

1回目不正解:
  → 別の具体例を使った再解説（同じ解説アプローチは使わない）
  → 再度質問受付 → 確認問題（別問題）

2回目不正解:
  → 概念をさらに細かいサブステップに分割して再解説
  → 「一緒に順番に考えてみましょう」という誘導型再解説
  → 再度質問受付 → 確認問題（さらに易しい問題）

3回目不正解:
  → ヒントあり確認問題に切り替え
  → ユーザーに「一旦次に進んで後で戻る」オプション提示
  → 「苦手マーク」として記録（後の学習プログラム調整に反映）

```

## 4. コンテンツ粒度設計

### 4.1 マイクロステップの構造

セッション内のステップを「マイクロステップ」という単位に分解する。

```
【Unit 2-3: 条件付き確率の応用】（セッション例）

  Micro-step 1: 条件付き確率の定義を理解する
    - 解説: 「条件付き確率とは何か」（テキスト + 天気の例）
    - 確認問題: 定義の言葉を問う問題

  Micro-step 2: P(A|B)の式の意味を理解する
    - 解説: 「式の分子・分母が何を意味するか」（ベン図アニメーション）
    - 確認問題: 式の各記号が何を表すかを問う問題

  Micro-step 3: 具体的な数値で式を使う
    - 解説: 「計算手順を例題で追う」（ステップバイステップ）
    - 確認問題: 数値を代入して計算する問題

  Micro-step 4: 文章題を式に変換する
    - 解説: 「文章のどの部分がA・B・A∩Bか見極める方法」
    - 確認問題: 文章題の各要素をA・B・A∩Bに分類する問題

  Micro-step 5: 応用問題を解く
    - 解説: 「複合的な条件付き確率の問題の解き方」
    - 確認問題: 実際の応用問題を解く

合計: 5マイクロステップ × 1サイクル = 1セッション（推定20〜30分）
```

### 4.2 マイクロステップ生成のルール

Claude Opus 4.8 が学習プログラム生成時に各マイクロステップを定義する際のルール：

| ルール | 詳細 |
|--------|------|
| 1ステップ1概念 | 1つのマイクロステップで扱うメインの学習目標は必ず1つ |
| 解説時間60〜90秒 | テキスト量は200〜400文字以内（読み上げ基準） |
| 依存関係の明示 | 前のステップを完了しないと次に進めないステップを明示 |
| 具体例必須 | 必ず1つ以上の具体的な例を含む |
| 視覚化要素の指定 | テキストのみ / 図が必要 / アニメーションが有効 を明示 |
| 再解説アプローチ予約 | 不正解時に使う「別の説明アプローチ」を事前に生成 |

### 4.3 マイクロステップのデータ構造

```typescript
interface MicroStep {

  sessionId: string
```

## 5. 確認問題設計

### 5.1 確認問題の種別

| 種別 | 説明 | 適用場面 | 例 |
|------|------|---------|-----|
| `shortAnswer` | 短文回答（1〜3文） | 定義・概念の確認 | 「条件付き確率とは何か説明してください」 |
| `multipleChoice` | 4択選択式 | 用語の識別・理解確認 | 「P(A\|B)の分母は何を表すか？ A〜D」 |
| `calculation` | 数値計算（記述） | 公式の適用確認 | 「P(A\|B)を計算しなさい（数値問題）」 |
| `explanation` | 理由・プロセス説明 | 深い理解の確認 | 「なぜ分母がP(B)になるのか説明してください」 |

### 5.2 確認問題の設計原則

```
【良い確認問題の条件】
  ✓ 今解説した概念だけで解ける（新しい知識は不要）
  ✓ 記憶の確認ではなく「理解の確認」になっている
  ✓ 「丸暗記した」だけでは答えられない
  ✓ 正解/不正解が採点者によらず一意に判断できる
  ✓ ヒントなしで解けるが、ヒントがあれば難易度が適切に下がる

【悪い確認問題の例（禁止）】
  ✗ 「条件付き確率の式は何ですか？」（丸暗記で答えられる）
  ✗ アセスメントで出た問題と同じ問題
  ✗ 2つ以上の新概念を同時に必要とする問題
  ✗ 計算が複雑すぎて「式の理解」が測れない問題
```

### 5.3 採点基準設計（Claude Haiku 4.5 への採点指示）

各確認問題に `rubric`（採点基準）を付与し、Haikuが一貫した採点ができるようにする。

```typescript
// 採点プロンプト骨格
const QUIZ_EVALUATION_PROMPT = `
あなたは採点者です。以下の基準に従って厳密に採点してください。

【学習した概念】
${microStep.concept}

【確認問題】
${quizQuestion.questionText}

【模範回答】
${quizQuestion.sampleAnswer}

【採点基準（Rubric）】
${quizQuestion.rubric}

【ユーザーの回答】
${userAnswer}

以下のJSONのみを返答してください：
{
  "verdict": "correct" | "partial" | "incorrect",
  "score": 0.0〜1.0,
  "correctElements": ["正しく理解できている部分の説明"],
  "incorrectElements": ["誤っている・不足している部分の説明"],
  "feedbackMessage": "ユーザーへの具体的なフィードバック（200文字以内）",
  "misunderstoodConcept": "つまずきポイントのタグ（再解説選択に使用）"

`
```

### 5.4 部分正解の処理

```
部分正解（partial）の場合:
  ・正しい部分を明確に褒める
  ・不足・誤りの部分を具体的に指摘する
  ・scoreが0.7以上 → 「ほぼ正解」として次のステップへ進む
  ・scoreが0.7未満 → 不正解と同様に再解説フェーズへ
```

## 6. Q&A処理設計

### 6.1 Q&A質問タイプの分類

Haikuが質問を受け取ったとき、まず質問タイプを分類する。

```typescript
type QAQuestionType =
  | 'CONCEPT_CLARIFICATION'   // 「〜とはどういう意味ですか？」
  | 'EXAMPLE_REQUEST'         // 「別の例を見せてください」
  | 'PROCESS_QUESTION'        // 「なぜ〜になるんですか？」
  | 'CALCULATION_HELP'        // 「この計算合ってますか？」
  | 'SCOPE_ADJACENT'          // 関連するが今のステップ外の質問
  | 'OUT_OF_SCOPE'            // 全く関係ない質問（脱線）

// 各タイプに応じたHaikuへの回答指示
const QA_TYPE_INSTRUCTIONS: Record<QAQuestionType, string> = {
  CONCEPT_CLARIFICATION: '定義を別の言葉で言い換え、最小限の例を1つ添えて答える',
  EXAMPLE_REQUEST: '今の説明とは異なる具体例を1〜2個出す',
  PROCESS_QUESTION: 'なぜそうなるかの論理的な説明を、ステップバイステップで答える',
  CALCULATION_HELP: 'ユーザーの計算を引用しながら、どこが正しく/間違っているかを指摘する',
  SCOPE_ADJACENT: '簡潔に答えた上で「詳しくは後で学ぶよ」と伝える',
  OUT_OF_SCOPE: 'メモして学習に戻るよう誘導する（回答は提供しない）'
}
```

### 6.2 Q&A回答の長さ制限

AIの回答が長すぎると理解の妨げになる。Haiku へのトークン制限を設定する。

| 質問タイプ | 最大出力トークン | 理由 |
|-----------|----------------|------|
| CONCEPT_CLARIFICATION | 300 | 簡潔な言い換えで十分 |
| EXAMPLE_REQUEST | 400 | 例は1〜2個に絞る |
| PROCESS_QUESTION | 500 | 論理展開が必要なため少し長め |
| CALCULATION_HELP | 400 | 計算ステップを明示 |
| SCOPE_ADJACENT | 200 | 簡潔に答えて誘導 |

### 6.3 脱線検知詳細設計

```
【脱線検知の判定フロー】

① 質問テキストを受信
② Claude Haiku 4.5 で関連度スコア（0.0〜1.0）を算出
   ・現在のマイクロステップのconcept
   ・現在のセッションのtopicTags
   ・ユーザーの質問テキスト
   を入力として関連度を判定

③ 判定結果に応じた処理:
   ・0.85以上: 完全に関連 → 通常Q&A回答
   ・0.70〜0.84: 関連するが周辺 → SCOPE_ADJACENTとして回答
   ・0.50〜0.69: やや脱線 → 「今の話に少し関係しているね。
                               簡単に答えるけど、今は○○に集中しよう！」
   ・0.50未満: 完全に脱線 → 「おもしろい質問だね！
                               今は○○の学習中だから、
                               後で一緒に考えよう。メモしておくね！」

④ 脱線として処理した質問は `pendingQuestions` に保存
   （セッション完了後または次のセッション開始時に確認）
```

### 6.4 Q&Aループの終了条件

```
Q&Aループは以下のいずれかで終了する:

  ① ユーザーが「分かりました」「大丈夫です」「次に進みたい」
     等の意思表示をした場合（Haikuが意図を検出）
  
  ② ユーザーが「✅ わかりました！次へ」ボタンを押した場合
  
  ③ Q&A回数が5回を超えた場合
     → 「たくさん質問してくれてありがとう！
         では確認問題で理解を確かめましょう！」と自動誘導

  ④ 同じ質問（または非常に近い質問）が2回繰り返された場合
     → 理解が進んでいない可能性を検知
     → 「もしかして、まだ腑に落ちていないところがある？
         確認問題の前に、もう少し別の例で説明しようか？」と提案
```

## 7. 再解説設計

### 7.1 再解説アプローチの種類

不正解時に使う再解説は、最初の解説とは必ず異なるアプローチを使う。

```typescript
type ReExplanationApproach =
  | 'DIFFERENT_EXAMPLE'      // 別の具体例（日常生活の別シーン）
  | 'SIMPLER_ANALOGY'        // より身近な比喩・アナロジー
  | 'STEP_BY_STEP_BREAKDOWN' // さらに細かいサブステップに分解
  | 'VISUAL_FIRST'           // 図やアニメーションを先に見せる
  | 'COUNTER_EXAMPLE'        // 「〜でないケース」から理解させる
  | 'NUMERIC_FIRST'          // まず数字で具体的に計算させてから概念化
```

### 7.2 再解説アプローチの選択ロジック

```
【再解説アプローチ選択】

入力:
  - misunderstoodConcept: どこでつまずいたか（採点結果から）
  - attemptCount: 何回目の不正解か
  - previousApproach: すでに使ったアプローチ
  - visualizationType: 元の解説タイプ

選択ロジック:
  if (attemptCount === 1) {
    // 1回目: 誤解ポイントに応じたアプローチ選択
    if (misunderstoodConcept === '式の意味理解') → VISUAL_FIRST
    if (misunderstoodConcept === '具体化できない') → DIFFERENT_EXAMPLE
    if (misunderstoodConcept === '論理の流れ') → STEP_BY_STEP_BREAKDOWN
    else → SIMPLER_ANALOGY
  }
  if (attemptCount === 2) {
    // 2回目: 前回と異なるアプローチ + サブステップ分割
    → STEP_BY_STEP_BREAKDOWN（必ずサブ分割）
  }
  if (attemptCount >= 3) {
    // 3回目: ヒントあり問題 + 段階的誘導
    → NUMERIC_FIRST（数字から入って概念に戻る）
    + hintEnabled: true
  }
```

### 7.3 再解説の会話例

```
【1回目不正解後の再解説例（DIFFERENT_EXAMPLE アプローチ）】

先生: 「惜しかったです！少し角度を変えて考えてみましょう。

      今度はカードゲームで例えますね。

      ─────────────────────────────────────────
      🃏 トランプの例
      
      52枚のトランプから1枚引きます。
      
      ・普通の確率: ハートを引く確率 = 13/52
      ・条件付き確率:「赤いカードだった」とわかっている。
        その上で、ハートである確率は？= 13/26
      ─────────────────────────────────────────

      「赤いカード」という条件がつくと、
      分母が52から26に減りましたね。

      これが条件付き確率のポイントです。
      条件がつくと「確率の空間が絞り込まれる」んです！」

【2回目不正解後の再解説例（STEP_BY_STEP_BREAKDOWN アプローチ）】

先生: 「大丈夫！一緒に1ステップずつ確認しましょう。

      まず、『確率の空間』ってわかりますか？

      [sub-micro-step A: 確率の空間とは]
       → 確認: 「全事象とは何か？」の確認問題
       → 正解後に続く

      [sub-micro-step B: 条件をつけると空間が変わる]
       → 確認: 「条件後の全事象の例」の確認問題
       → 正解後に続く

      [sub-micro-step C: 式の分母は絞られた空間]
       → 確認: 「なぜ分母がP(B)なのか」の確認問題

      3つ全部理解できたら、元の問題に戻ってみよう！」
```

### 8.2 ヒント表示UI

確認問題に「ヒント」機能を追加する。ヒントは3段階で段階的に開示する。

```
【ヒントボタン押下後の段階的表示】

1回目押下（最小限のヒント）:
  💡「P(A|B)の式を思い出してみて。分母はどの文字？」

2回目押下（中程度のヒント）:
  💡「条件は『白玉だった』ということ。その確率が分母になるよ。」

3回目押下（ほぼ答え）:
  💡「P(B) = 白玉を取り出す確率 = 白玉の数 / 全玉の数」

※ ヒントを使った場合でも正解は正解として扱う
  （ヒント使用フラグを記録し、習熟度スコアは0.8で記録）
```

### 8.3 スキップ機能

```
【解説スキップ】
  読み上げ中に「■ スキップ」ボタンを押すと読み上げを停止し、
  テキストのみ表示のまま「質問/わかった」選択に進む

【ステップスキップ（上級者向け）】
  「もう知っています」ボタンで確認問題のみに直接飛ぶ
  ・正解 → そのステップは「既習」として記録（習熟度1.0）
  ・不正解 → 「実は知らなかったね！一緒に学ぼう」と通常フローに戻す

【ユニットスキップ（設定で有効化）】
  「このユニットをスキップ」→ 全マイクロステップに対してスキップ問題を出題
  → 全問正解でユニットスキップ確定
  → 1問でも不正解で「苦手があるので学習を推奨」と提案
```

### 10.1 解説コンテンツ生成（Claude Haiku 4.5）

アセスメント完了後の学習プログラム生成時はOpusで骨格を作るが、**各マイクロステップの解説コンテンツ本文はセッション直前にHaikuで生成**する。これによりコスト削減と応答速度を両立する。

```
【解説コンテンツ生成タイミング】

・プログラム生成時（Opus）:
  各マイクロステップの概念定義・構成・確認問題Rubricを生成
  （コンテンツ本文は生成しない）

・セッション開始直前（Haiku）:
  当セッションに含まれる全マイクロステップの解説本文を事前生成
  （待ち時間なしでスムーズに進むよう、一括でプリフェッチ）

・再解説時（Haiku）:
  不正解の都度、リアルタイムで別アプローチの再解説を生成
  （evaluationResultのmisunderstoodConceptを入力として活用）
```

```typescript
// 解説コンテンツ生成プロンプト（Claude Haiku 4.5）
const EXPLANATION_GENERATION_PROMPT = `
あなたは優れた個別指導の先生「さくら先生」です。

【学習テーマ】: ${subject}
【現在のユニット】: ${unitTitle}

1. 解説は1つの概念だけを扱う
2. 読み上げ時間が60〜90秒になるよう分量を調整
3. 必ず1つの具体例を含める
4. 難しい用語を使う場合は直後に言い換える
5. 最後に「このポイントが大事です」と1文でまとめる
```

### 確認問題2回不正解の場合の完全フロー

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 Micro-step: 条件付き確率の定義を理解する（2回不正解ケース）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

① 解説フェーズ
先生: 「条件付き確率とは、Bが起きたとわかった上でAが起きる確率のことです。
      [天気の例 + ベン図アニメーション]
      式: P(A|B) = P(A∩B) / P(B)」

② 質問受付
先生: 「どうでしたか？」
ユーザー: [✅ わかりました！] を選択

③ 確認問題（1回目）
先生: 「袋の中に赤玉3個・白玉2個・青玉1個。
       白玉を取り出したとき、P(B)は何の確率ですか？」
ユーザー: 「玉を取り出す確率です」

④ 採点・フィードバック（不正解・1回目）
先生: 「惜しい！もう少し具体的に考えてみよう。
       Bという条件は『白玉だった』ということだよ。
       では別の例で一緒に考えてみよう！」

⑥ 再解説フェーズ（DIFFERENT_EXAMPLE アプローチ）
先生: 「今度はトランプで考えましょう。
       [トランプの例 + 新しいアニメーション]
       赤いカードを引いたとわかった上で、それがハートの確率。
       この場合のP(B)は？」
ユーザー: 「なんとなく分かってきた気がします」

② 質問受付（2回目）
先生: 「質問はありますか？」
ユーザー: [✅ わかりました！]

③ 確認問題（2回目、別問題）
先生: 「サイコロを1回振って6が出た。
       P(A|B)を計算するとき、B = 偶数の目の場合、P(B)はいくつですか？」
ユーザー: 「3/6です」

④ 採点（不正解・2回目）
先生: 「おしいー！計算自体は合ってるよ。
       でも、B = 偶数の目 のとき P(B) = 3/6 は正解！ 
       あ、ごめん、実はこれ正解だったね！」

★ ここで採点ロジックの再確認が必要（正解の場合）

…（正解なら正解フィードバックへ）

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

3回連続不正解ケース（サブステップ分割）:

⑥ 再解説フェーズ（STEP_BY_STEP_BREAKDOWN アプローチ）
先生: 「大丈夫！一緒に一歩ずつ確認しよう。

       【サブステップA】
       まず確認：「全事象」ってどういう意味？
       袋に赤3・白2・青1のとき、全事象は何通り？」
ユーザー: 「6通りです」
先生: 「正解！全部で6通りだね。

       【サブステップB】
       次に：条件がつくと「世界が狭まる」んです。
       「白玉だった」という条件がつくと、
       「起こりうる世界」は白玉の中だけになるよね。
       その世界は何通り？」
ユーザー: 「2通りです」
先生: 「そう！2通り。これが条件後の全事象です。
       これがP(B)の分母の『世界』なんです。

       【サブステップC】
       では、P(B) = 白玉の世界 / 全体の世界 は？」
ユーザー: 「2/6です！」
先生: 「完璧！P(B) = 2/6 = 1/3 です。
       さっきまで難しかったのに、段階的に考えると解けたね！」
```
